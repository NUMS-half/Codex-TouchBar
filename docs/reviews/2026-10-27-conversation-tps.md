## 交付行为

- 「设置 → 通用 → 会话速度」提供菜单栏和输入框两个独立开关，默认关闭，覆盖四种组合。
- 菜单栏保留原有两行额度；启用 TPS 后在旁边显示单色速度，关闭恢复原宽度。
- 输入框使用透明、鼠标穿透、不能成为键盘焦点的原生浮层；切离 Codex、最小化、归属不明或关闭时撤下。
- 按用户后续指定，沿用 CodexStatusbar 的分级定位：Context → model → composer → window。提供窗口相对位置、水平／垂直偏移与文字外观。通用页使用原生滚动，保持原有字体、颜色、圆角及设置分组样式。
- TPS 失败局部降级，不清空额度、不改变额度刷新策略、历史或提醒。关闭两个位置后停止共享观察器；菜单栏单独使用无需辅助功能权限。

## 数据与计算

当前用户拥有的本地 IPC 只发送初始化，随后被动跟随对话；只读、参数化查询同一数据目录的日志路径，并校验路径和日志头部 ID。不会按文件修改时间猜当前对话，不读取登录凭据或直接访问模型服务。

尾读从 4 MiB 起，有明确上限；文件事件触发追加读取，保留半行并限制超长记录。只解码所需的计数、类型、时间和内存中的 ID，不保存正文、原始帧或真实会话 fixtures。

模型时间使用 Reasoning/AgentMessage 区间并集，工具活动不计入。累计用量替换、响应 ID 去重，避免两种 carrier 重复计数。当前日志中的 `turn_token_usage` 可能是整段对话累计值，未将它直接用于本轮分子。

计时与用量分批到达时保持最后确认的测量，在 token_count 边界提交；缺少该 carrier 的现代日志到 task_complete 再确认。损坏记录或未知模型类别使本轮不可测，并撤销累计基线，防止下一轮继承错误。真实日志存在毫秒取整后的零长度模型 item：它贡献零时长；缺失、负向时间仍使本轮失效，整体不足 0.5 秒不显示速率。

## 审查中修正的问题

1. IPC 多帧合并读取：Foundation Data 移除前缀后 startIndex 不归零；改为以实际起始下标读取，并由分片／合并帧测试覆盖。
2. 旧 token 数与新模型时间混算：保存已确认测量，补充 item 先到、usage 先到两种延迟顺序的快照检查。
3. 损坏或超长模型记录被忽略：本轮失效，撤销旧累计基线；测试覆盖损坏后的下一轮及旧格式计数。
4. 未支持来源或被替换的日志：每次核对头部，不因首次失败后记录 inode 而绕过后续验证。
5. 浮层过期几何：布局通知递增版本，在途旧扫描不能重新恢复旧位置；增加窗口移动、尺寸与最小化通知。
6. 原始 AX 候选位置未检查控件：可识别结构时检查安全容器和邻近控件，空间不足隐藏。窗口 fallback 是用户明确选用的兼容路径，不宣称具备同等几何精度。

独立审查已复核修复，最后一轮未发现新的 Critical/Required 问题。诊断使用合成日志、隔离偏好与假通知；未用模拟硬件冒充实体 Touch Bar 验收。

## 兼容边界

本机 Codex 的 AX 窗口存在，但其输入区域树未暴露；尝试 Electron 官方的 AXManualAccessibility 也未能展开。没有设置会模拟 VoiceOver 的 AXEnhancedUserInterface，不启用录屏、远程调试或客户端注入。

因此已验证的真实显示路径是窗口回退。回退坐标采用参考项目的点偏移，窄窗口、侧栏或布局变化可能需要用户调整；不能把此次可见性验收说成 Context/model 精确贴靠验收。Context/model 搜索还依赖先识别 textarea 的父容器，其在其他 Codex 版本上的真实命中率尚未验证。

多窗口无法确认焦点与 IPC 路由的对应关系时暂时不显示；远端／云端会话缺少匹配的本地日志时不可用。跨屏、全屏/Spaces、不同 Codex 版本及两类实体 Touch Bar 硬件的完整真机矩阵仍需后续验收。
