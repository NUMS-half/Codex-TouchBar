# TPS 闪烁、焦点返回与重复计算审查

日期：2026-10-28。不提交、不发布；保留现有显示格式、计算口径与 UI 风格。

## 审查结论

1. **Required：单次识别失败导致数值闪烁及重复重放。** 标题暂不可读和索引暂不可读都会立即清除 selected/reader，发布 `—`，下一次成功又发布 waiting 并重放日志。已用假标题暂失复现失败，再验证修复。
2. **Required：主线程同步查询系统窗口并放大 UI 更新。** MainActor `pushSessionTPS` 原先重复调用 `CGWindowListCopyWindowInfo`；TPS 每次变化还触发 `UsageStore.onChange → pushState`，更新额度卡、Touch Bar 呈现与菜单状态。对原安装版自身进程进行 2 秒只读调用栈采样，捕捉到了 `updateSessionTPS → pushState → pushSessionTPS → windowCount` 主线程路径。它是明确的阻塞风险；该采样没有量化重现用户那次旋转鼠标的完整持续时间。
3. **确有重复解析：** A → B → A 原先创建三个 reader，每次重读小文件或重放 4/8/16 MiB 恢复窗口。只有同一 reader 连续追加时才是增量。
4. **确有重复查询／计算：** 每 500ms 重开 SQLite 并执行完整标题表达式查询；读取 modelSeconds 时反复排序区间，读取 output 时反复汇总响应 token。

## 已实施修复

- MainActor TPS 渲染移除所有原生窗口查询；TPS 使用独立通知，只刷新自己的标签／快捷位置，重复相同状态不通知。
- 区分暂不可读与已确认切换／歧义。暂不可读在同一已确认会话上最多宽限 1.5 秒；超过期限清空。已确认不同会话、新轮次、重名或未知页面仍撤销旧显示，不无限保留旧值。
- 后台暂停窗口采样，保留 worker、文件监听和计算状态；返回前台重新确认窗口，不销毁重建观察器。关闭全部功能、Codex 退出／睡眠时仍完整清理。
- 合并订阅重放批次；只读 SQLite 连接与 prepared statement 复用，最多 8 个标题结果，以数据库身份和 data_version 失效。
- 最近 4 个 reader 使用 LRU 检查点。只保留数字计算状态、标识与偏移，丢弃 partial 原文；校验文件身份／大小／修改时间。不变文件零内容读取／零 JSON 解析，追加从偏移继续；原位同长度改写、截断和替换重新恢复。
- 模型区间总时长和响应 token 汇总在新增记录时更新，读取快照无需排序或再次求和。计算仍为每轮模型平均速度，包含推理、排除工具间隔。
- 显示层只改动配置为 TPS 的快捷位置；普通快捷位置不再因 TPS 值变化重设字体／辅助功能角色或标记重排／重绘。文本相同只更新说明，不重复设置面板或 Touch Bar 数值文字。

## 已执行验证

- 先观察“短暂标题失败不应闪烁”和“A-B-A 不应重建 A reader”回归失败，再修复通过。
- 假资源测试：A-B-A reader 创建次数为 2；100 次稳定标题采样执行 1 次标题查询；80 条订阅事件合并为有限次窗口采样；窗口采样未在 UI 线程运行。
- 焦点离开暂停原生采样且数值保留，返回不重建 reader；后台新增 task_started 的缓存日志回访立即清空旧轮，随后增量完成更新。
- 缓存超过四会话安全淘汰；未知、重名、持续失联、权限说明及旧回调隔离保持覆盖。
- 不变日志内容读取与解析均为零；partial 检查点恢复不重放。独立复核补充同 inode／同长度原位改写，先复现旧值残留，再修复失效判断。
- 临时禁用 reader 快路径，零读取断言确实失败，随后恢复源码。独立复核确认无剩余 Required。
- 显示层回归确认普通快捷位置在 TPS 更新后不标记重排或重绘；最终显示层优化后的核心、TPS／效率及设置自检再次通过，签名有效。

上述为操作次数和行为回归，未将其转换成未经测量的延迟百分比或“彻底消除系统转圈”的结论。首次打开、缓存外会话及已改变的日志仍需读取／计算；真实窗口与 Touch Bar 的交互流畅度仍需实机试用。

最终 `./build.sh` 构建与固定证书签名成功；签名构建的 `--self-test`、`--session-tps-ui-self-test`、`--settings-self-test`、`--monitoring-ui-self-test` 及严格签名校验均通过。Command Line Tools 环境的 XCTest 仅确认编译链接，行为验证以实际执行的应用自检为准。
