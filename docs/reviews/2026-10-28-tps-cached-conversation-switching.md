# 返回已访问对话时 TPS 不更新

日期：2026-10-28。范围：当前可见对话识别、订阅集合、诊断及必要权限说明。不提交、不发布。

## 根因

实际本地 IPC 检查发现，同一 source 会长期保留多个对话的订阅；initialize 会重放多个 `following=true`，A → B → A 的最后一步没有新的订阅变化。原实现将订阅变化当作可见对话切换，且一个 source 只保存一个 route，故首次访问更新而再次访问沿用最后新订阅的数值。

## 修复

- 仅读取唯一可见 Codex 原生窗口的标题，在本地只读索引中精确唯一匹配有效 name/title，再验证本地订阅；不以订阅顺序、最近日志写入或最近访问推测当前对话。
- 观测启用期间每 500ms 检查可见标题；A → B → A 即使没有新订阅通知也重新绑定 A 的日志。一个 source 保留多个订阅，取消 B 不再误删 A。订阅集仍有边界，上限调整为 4096 以容纳缓存视图。
- 无法读取、标题重名、多窗口、未知页面或缺少本地订阅时清空旧值；禁止沿用上一页面 TPS。重名暂不显示是明确的保守边界。
- 现有窗口标题访问可用时直接使用；否则只复用已授权的 AX 窗口标题访问。不展开 AX 树、不读取正文、不自动提示、不请求屏幕录制。通用设置增加按用户点击触发的「授权识别当前对话…」，保留既有控件样式。
- 旧文件和旧连接回调通过 generation 隔离，避免切换后清除或覆盖当前 reader。此前完成保留与下一轮重置逻辑不变。
