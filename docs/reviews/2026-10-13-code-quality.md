# 2026-10-13 代码质量审查

## 范围与原则

按code-review-and-quality技能的正确性、可读性、架构、安全、性能五个维度审查核心数据、刷新调度、权限、提醒、历史与界面自检。独立审查者进行只读复核，主代理实施修改和执行验证。本轮沿用此前未提交的功能改动，未改动用户新增的技能目录。

保留现有额度口径、提醒规则、快捷操作与Touch Bar尺寸；旧偏好键名、应用标识、快照和历史文件路径不变。生产逻辑整理和异常输入／调度修复分开记录，避免把新功能混入规范整理。

## 完成项目

| 分类 | 原问题 | 改进 |
| --- | --- | --- |
| 架构 | 刷新策略文件包含偏好自检，且反向依赖偏好层的间隔列表 | 自检移入RefreshPolicyChecks，间隔与名称由QuotaRefreshPolicy统一拥有 |
| 去重 | 设置和监控自检重复遍历／渲染视图，设置测试依赖监控测试实现 | UIDiagnosticSupport统一遍历和PNG生成，使用独立渲染错误类型 |
| 维护性 | App标识、目录和偏好键名散落，保留了仅自检使用的旧单一间隔包装 | ApplicationIdentity统一标识及目录；Preferences集中键名，直接使用refreshPolicy访问间隔 |
| 性能 | 同值Touch Bar设置仍发送重绘通知 | 同值写入直接返回，新增通知计数检查 |
| 正确性（P2） | 任意App切换都会重置额度计时器，后台刷新可能一直延后 | QuotaRefreshTimer保留同类前后台状态的查询时间；设置变化、唤醒仍显式重建，停止后丢弃失效回调 |
| 数据边界 | 未完成RPC行没有长度上限；异常缓存百分比与倒计时可能整数溢出 | 按单行累计限制4MiB，允许大块短消息；先限制百分比再相减，安全转换倒计时 |
| 可读性 | 版本判断通过条件表达式强制解包提醒引擎 | 改用显式可选绑定与版本检查，沿用原回退行为 |
| 规范 | 贡献指南仍描述临时签名和旧刷新控件位置 | 更新固定签名、统一设置、实际自检与模块维护约定 |

## 验证

- `./build.sh`：构建debug、release及测试目标，固定证书签名成功。Command Line Tools环境没有输出XCTest执行记录，因此不把编译测试目标当作已执行测试。
- `--self-test`：实际执行刷新开关、偏好去重、迁移、协议帧边界、百分比／日期异常值、历史和提醒逻辑检查。
- `--settings-self-test --settings-preview build/code-quality-previews/buttons.png`：实际验证保存／取消、七类刷新设置、Touch Bar展开按钮边界、刷新与返回回调、浅色／暗色布局。
- `--monitoring-ui-self-test`：实际验证后台状态切换不推迟查询、前后台转换、间隔变化、禁用与停止、通知／登录项替身、刷新动画、曲线密集标记及满量历史渲染。
- 变异验证①：反转刷新允许条件，自检退出1；从副本自动恢复源文件。
- 变异验证②：反转调度器的前后台状态比较，监控UI自检以“background app switching preserves refresh deadline”失败；从副本自动恢复源文件。
- `git diff --check`：检查空白错误。安装使用现有install.sh，保持固定签名身份。

所有自动检查使用临时历史、隔离偏好和通知替身，没有发送真实测试通知、调用真实ChatGPT菜单或改写用户历史。离屏验证不能替代实体Touch Bar与系统通知的人工验收。

## 复核结论

独立复审未发现阻塞问题。本轮发现的后台调度问题已修复；输入保护包含整行超限、分段累积超限、拒绝后的缓冲释放、总大小超过4MiB但每行合规的通知批次。

未引入第三方包、网络服务或账户身份存储。发布与Git提交仍由后续明确指令决定。
