# 快捷操作反馈与额度卡片间距

## 原因与调整

- 快捷操作页原先将保存、取消反馈写入功能目录的提示区域，离按钮较远，后续目录读取结果也能覆盖它。两个按钮在没有草稿修改时仍然可点；“取消”实际只撤销草稿，没有关闭窗口。
- 保留预览、保存的编辑方式，避免选择功能或输入名称时立即修改真实 Touch Bar。“取消”改为“撤销更改”；独立的状态文字放在按钮左侧并右对齐，显示尚未修改、待保存、已保存或已撤销。只在规范化后的配置有实际差异时启用保存和撤销，目录读取不会改写这些反馈。恢复默认仍需保存才应用。
- 额度卡原先固定高 116 pt，数字从上定位，进度条从下定位，实测两者的布局间距为 20 pt。改为从数字向下衔接进度条，让内容决定高度；间距为 8 pt，卡高为 104 pt。字体、配色、卡片材质、边框、左右内边距和面板宽度保持原样。

## 验证

- 修改前，新增的设置检查因缺少明确的撤销语义和独立反馈失败；额度检查测到 20 pt 间距、116 pt 卡高并失败。
- 还临时反转新增的修改状态判断，设置检查正确报告“unchanged shortcut actions are disabled”失败，随后恢复正确代码。
- 实际执行 `--self-test`、`--settings-self-test --settings-preview …`、`--monitoring-ui-self-test`。设置检查覆盖待保存、保存、撤销、恢复默认、目录结果覆盖风险、规范化后相同的输入、页面切换和关闭窗口。卡片检查覆盖浅色／深色的正常、低额、旧数据及缺失状态，数字与进度条间距均为 8 pt。
- 实际执行原生 `--panel-motion-self-test`，使用 ScreenCaptureKit 捕获诊断进程自己的完整弹出面板，检查了浅色／深色的箭头、主体及卡片；三次展开／返回及中途反向操作均无控件裁切，窗口顶部漂移为 0 pt。截图位于 `build/ui-polish-native/native-overview-{light,dark}.png`，设置截图位于 `build/ui-polish-release/`。
- `./build.sh` 完成构建与固定证书签名。当前 Command Line Tools 环境的 XCTest 只确认构建；上述可执行程序自检的通过结果单独确认。
- 检查范围仅为这两项修复及相应回归验证；没有修改额度读取、TPS 计算或 Touch Bar 槽位显示。自动验证使用隔离偏好、示例额度及假通知，没有呈现实物 Touch Bar；不宣称实体硬件验收。

## 代码复核

- 配置比较复用已有的规范化规则，保存前再次读取输入控件；没有差异时不重复写入或通知。
- 草稿、目录结果及编辑反馈各自保留职责，没有新增定时器、网络请求、依赖或持久化字段。
- 卡片以完整纵向约束链确定自然高度；正常、缺失及旧数据使用同一布局，不额外叠加背景材质。
- 未发现本次改动中需要继续修复的问题。工作保持未提交，不发布。
